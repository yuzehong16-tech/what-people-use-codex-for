这个没什么好说的。

Codex 本身就是 Coding Agent。

但现在所谓“用 Codex 写代码”，和以前让 ChatGPT 写一段代码已经不是一回事了。

以前是：

> 帮我写一个登录接口。

现在Codex更像：

> 这个项目登录偶尔失效，帮我找一下原因，修完以后跑测试，不要破坏现有接口。

所以程序员现在真正大量使用Codex的地方，并不一定是“从零写代码”。

反而是那些以前特别耗时间的事情：

修Bug。

读陌生项目。

重构。

补测试。

写脚本。

改接口。

处理依赖。

查日志。

做迁移。

甚至接手一坨自己半年前写的、现在已经完全看不懂的代码。

这种场景是真的舒服。

## 但如果你不是程序员，我觉得反而有另外一套玩法

这个也是最近很多人容易误解Codex的地方。

看到“Coding Agent”，觉得：

**我不会编程，所以和我没关系。**

其实现在有AI以后，“代码”越来越像一个中间过程。

你不一定需要会写。

你只需要知道：

**最后想得到什么。**

举几个特别普通的例子。

## 1\. 我现在特别喜欢拿它处理Excel和CSV

比如公司丢给你一个Excel。

5万条数据。

让你：

删除重复项。

统一日期。

拆分字段。

找异常订单。

统计各地区销售额。

按照月份汇总。

最后生成几个CSV。

如果你Excel特别熟，当然可以Power Query、数据透视表、各种公式。

但很多普通人不会。

这时候我反而会直接把任务交给Codex。

让它写个Python脚本处理。

我根本不关心它Python写了什么。

我只关心：

**最后生成的Excel对不对。**

这其实是我觉得AI编程对普通人最有价值的地方。

以前：

不会编程 = 不能使用程序解决问题。

现在：

不会编程 ≠ 不能让程序帮你干活。

中间那层代码，Codex帮你写。

## 2\. 批量处理文件，这个真的很爽

这个我强烈建议不知道Codex干什么的人试一下。

看看自己电脑里有没有这种破事：

300张照片要改名字。

几十个PDF要分类。

500个Word文件要统一命名。

几千张图片要按照尺寸分类。

多个CSV要合并。

两个文件夹要找重复文件。

一批视频要统计大小、时长、分辨率。

这种工作人工做特别蠢。

但是你又不值得专门买个软件。

Codex就特别适合。

比如：

> 扫描这个文件夹，把所有照片按照拍摄年份和月份分类。不要删除原文件，先复制20张到测试目录验证，确认没问题再处理全部。

它写脚本。

执行。

最后给你结果。

这种任务你用一次以后，就开始知道Codex到底有什么用了。

## 6\. 我还会让Codex帮我研究一些完全看不懂的项目

这个对刚开始学编程的人特别有用。
